# C50：DET / INJECT / MASK 无主臂信号优化方案

日期：2026-09-17。代码基线：`det @ 5abe98adf452d1164047e7f7e0028fbcff29c7ad`。

状态：**规划，不代表已经修改模型、生成标签或启动训练。** 本轮仅新增本文档；暂不进行真机测试。文中的新配置、测试和实验名称均为待实现内容。

## 1. 目标与已经确定的边界

最终目标是至少一个模型准确、连贯地完成“接近 → 抓起 → 搬运 → 放下”，而不是单独提高检测 AP 或降低训练 loss。离线阶段只能筛选更有希望的候选，不能证明闭环抓取成功或已经消除机械臂抽搐。

| 正式组别 | 共同基础 | 唯一区别 | 部署时是否需要分割标签 / SAM |
|---|---|---|---|
| DET-NM | ACT + 原有 FPN / 检测特征融合 + FCOS 辅助监督 | 不额外注入 FCOS 特征；不加 MASK 监督 | 不需要 |
| INJECT-NM | 同 DET-NM | 额外使用 FCOS 检测特征；不加 MASK 监督 | 不需要 |
| MASK-NM | 同 DET-NM | 加入有效的分割辅助监督；禁止 FCOS 额外注入和 MASK 特征注入 | 不需要；正常动作推理不运行 mask decoder |

三组共同删除 `master_gripper.pos`，输入 state 从 9 维改为 8 维；六维动作保持不变。保留真实 follower 可取得的关节位置、夹爪位置、负载、电流，并检查这些字段的采集与部署单位、符号、顺序及有效性。

这里的 DET 基线本来就有检测特征融合。“不额外注入”不等于动作分支完全不使用检测相关特征。首轮不同时加入 mask injection、多层 token、不同数据规模、更大 backbone 等变化。

## 2. 项目证据：哪些问题已确认，哪些尚未确认

### 2.1 主臂信号必须从新的训练链路移除

既有固定 10 个验证 episode 共 7,180 帧中，`master_gripper.pos` 与当帧 `action.gripper.pos` 完全相等。这是当前动作标签泄漏，真机自主执行却拿不到该信号。

在预处理前置零该维后，夹爪归一化 MAE：DET 从 0.072558 增至 0.616372，INJECT 从 0.143583 增至 0.179937。INJECT 对该信号依赖较小，是继续研究它的依据；但这不证明其机械臂定位或闭环执行更好。

证据见 [部署一致评估报告](../报告/C50_部署一致主臂夹爪评估报告_2026-09-16.md)。新模型应真正删除这一维、重新计算训练集统计，而非继续训练九维模型后只在部署时补零。

### 2.2 MASK 当前存在确定的训练实现缺陷

代码：`src/lerobot/policies/act_det/modeling_act_det.py`。

- 第 570 行在加入总损失前对 mask loss 调用 `.item()`，使它成为不带梯度的数值；按这条路径，分割损失不会训练 decoder 或共享视觉骨干。`.item()` 不可微也与 [PyTorch 文档](https://docs.pytorch.org/docs/2.14/generated/torch.Tensor.item.html)一致。
- 第 485 行已经对 batch / 像素取均值，随后又除以累计帧数；同样误差随 batch size 被重复缩小。
- `_load_mask_batch()` 中任意一帧缺失会让整个 batch 放弃 mask 监督；缺目录也可能静默禁用。
- 前序源码最小复现中，同样的 0.5 像素误差，在 batch=1/4/8 时报告 0.5/0.125/0.0625，且没有 mask 梯度。完整模型集成回归仍需在实施阶段补齐。
- 当前 C50 无主臂信号派生数据尚没有配套 mask 标签。旧数据集 B 的 masks 不能仅凭 episode 编号复制过来。

因此，历史 mask loss 很小不能证明分割学好了，也不能据此否定分割辅助监督。这个确定缺陷不等于已经找到了真机抽搐的原因。

### 2.3 INJECT 有研究价值，但不能用检测准确替代动作准确

既有检测评估中 DET / INJECT 的 AP50 均为 1.0，平均框 IoU 约 0.882 / 0.877；在这些同分布图像上，检测本身已经较好。真机“有时偏离”仍可能来自特征到动作的映射、输入分布、时序或执行误差，不能只提高检测阈值处理。

当前 `detection/fcos.py` 注入方式为：拼接分类 / 回归塔中间特征，乘 `1 + sigmoid(centerness)`，投影后作为额外 token。需要验证的风险是：

- 门控范围为 1–2，不能抑制低置信区域；centerness 只在正样本位置受监督，背景上的值不能直接视为可靠前景概率。
- top 的 p4 增加 300 个 token，编码器输入约从 602 增至 902。注意力配对数量增加不等于整模型耗时按同一比例增加，必须测量。
- 动作梯度与检测梯度共同影响相关特征，是否冲突尚未测定。
- 检测 NMS / score 阈值不直接控制这条中间特征注入路径；调阈值未必改变动作。

既有 swap 方向一致性说明 INJECT 会对位置线索作出相应变化，但换杯子图像后仍用原动作标签计算误差，不是严格的语义保持鲁棒性测试。不能把“动作响应更强”直接解释为过度反应。

### 2.4 抽搐仍是待定位问题

以用户纠正后的现象为准：去掉的是 `max_relative_target`，不是去掉 `n_action_steps=5`；去掉限幅后仍卡顿；coeff=0.01 偏慢、略卡，coeff=0.1 实际动作更快但抽搐明显。

目前日志缺少同步的完整状态、原始动作块、图像采集时间和分段耗时，不能区分模型预测跳变、执行延时、图像异常与机械跟踪问题。原始主臂信号在演示起始区间本来就接近零，其置零效应不足以单独解释启动抽动。

## 4. 三组共同的数据与实验底座

### 4.1 固定范围，避免同时改变任务

1. 首轮使用目标检测标注已核验的 C50，不扩展到标注对齐尚有疑点的其余 40 个 episode。
2. 以 `数据集/formal1_C50_nomaster` 为派生数据基础，不覆盖原始 `formal1_C`。
3. 全部 50 个 episode 共 35,900 帧；训练 40 个共 28,720 帧。固定验证集：`[7,11,13,14,16,27,35,38,40,43]`。
4. 为选择超参数，在原训练 40 个 episode 内再固定约 32/8 的小训练 / 开发划分，按杯子位置和演示条件尽量分组、均衡；不拆同一 episode 的相邻帧到两侧。划分写入 manifest。
5. 小试统计仅用小训练部分；方案选定后，正式训练恢复 40 个 episode 并使用这 40 个的统计。既有 10 个验证 episode 已被反复查看，应称验证集，不能宣传为从未接触的最终测试集。

### 4.2 训练—部署契约与数据审计

- 元数据、parquet、processor、模型输入维度、真机组装字段全部一致为 8 维；按字段名删除，禁止盲删“最后一维”。检查 `master_gripper.pos` 未从其他路径再次进入模型。
- 六维动作数值、动作单位、关节顺序不变；检查 state/action 时间对应关系、相机 RGB/BGR、top/gripper 顺序及训练 / 部署归一化。
- 核对每帧对应的视频文件、时间戳和视频局部偏移，不能用全局 frame index 直接当作任意视频的局部帧号。
- 自动报告突变、重复帧、图像坏帧、长停顿和动作饱和，人工复核候选；不自动删除正常抓握、接触等待或全部静止帧。
- 检查夹爪 load / current 的真机可用性及分布。首轮仅删除 master；如另有字段不可用，先解决契约，再重新冻结所有组三方一致的输入方案。
- 保存数据、划分、统计、标签、代码 diff 和环境的摘要；同一轮比较使用相同公共权重初始化及样本顺序。仅设置同一 seed 不保证添加分支后公共层初始化仍相同，应显式复制、校验公共参数。

验收：原数据未改动；帧与标签一一对应；无跨划分统计泄漏；保存 / 重载后的输入处理及动作反归一化一致。

## 5. MASK 路线：先让监督真正生效，再改损失设计

### M0：有效的分割辅助监督，第一优先级

修改范围主要是 `modeling_act_det.py`、`mask_loader.py` 及相关回归测试：

1. 用仍带计算图的 Tensor 加入总损失，仅在写日志时 `detach().item()`；同步修正返回类型与日志接口。
2. 对有效像素 / 有效样本只归一化一次。复制相同样本扩大 batch，标量损失应保持不变；padding 和明确无效标注不能进入分母。
3. 开启 MASK 时，目录不存在、文件损坏、未声明的缺帧立即报错。对经审核明确标为“不确定”的帧使用显式 validity，不把它视作背景，也不静默跳过整批。
4. 仅 top 相机启用分割；保持 `fcos_feature_inject=false`、`mask_feature_inject=false`。
5. 第一对照暂保留现有 sigmoid + L1，以隔离“修复训练有效性”的收益。正确归一化后的 `mask_weight=0.1` 仅作为小试起点，不是最佳值；旧的 1.0 因梯度中断及重复归一化，不可与新权重直接比较。

必须先通过的测试：

- 合成数据验证梯度连接、batch 重复不变性、缺帧报错及有效像素归一化。
- 真实模型前向中，单独反传 MASK 损失后 decoder、FPN、共享 backbone 获得有限、非零梯度；优化器确实包含这些参数。
- mask_weight=0 时，无来自 MASK 损失的梯度；检测 / 动作分支仍可正常训练。
- 训练集选取覆盖接近、抓握和放下的 32–64 帧做约 300 步小样本拟合，确认前景 IoU / Dice 明显优于全背景基线，保存预测叠图。loss 下降但持续全黑视为失败，不能进入正式训练。
- checkpoint 保存 / 加载一致；普通动作推理既不读取 mask 文件，也不调用 mask decoder / SAM。辅助评估显式开启 decoder 时另算耗时。

### 标签准备：先抽检，再批量生成

采用现有 SAM 2 离线生成方案；其视频传播能力可见 [SAM 2 官方仓库](https://github.com/facebookresearch/sam2)。伪标签不是人工真值，透明杯轮廓、遮挡、夹爪重叠必须检查。

- 先做 3–5 个训练 episode 预览，再生成 C50。每个 episode 至少审核接近、闭合、抬起、搬运、放下的关键帧，另查看面积突变、质心跳变、空掩码等自动异常清单。
- 现有生成脚本含固定视频路径、起始帧等假设，实施时核对 `scripts/generate_sam2_masks.py` 的元数据映射；首个有效框若不在 frame 0，不能冒充 frame 0 的提示框。
- 当前生成逻辑先阈值化 SAM logits 再高斯模糊，输出是软化轮廓，不是校准概率。保留原始二值标签及可复现的软化参数，不重复 sigmoid。
- 区分真实空前景、目标遮挡、生成失败和缺帧；禁止把传播失败自动补零当真值。
- 100% 帧必须有明确的标签状态与对齐记录；全部可监督帧必须有有效文件。逐 split 报告监督覆盖率及忽略原因，不能靠忽略困难样本掩盖问题。
- 为检验“分割准确”而非仅拟合 SAM，另准备少量人工修正的分层抽查帧；只用于评估的标注不得进入训练。IoU 若仅对 SAM 计算，应标明为伪标签一致性。

### M1：仅在 M0 出现前景学习不足时启用

候选损失为 `BCEWithLogits + soft Dice`。decoder 输出 logits，BCE 内部处理 sigmoid，Dice / 可视化再转换概率，避免重复 sigmoid。[PyTorch 对该接口的说明](https://docs.pytorch.org/docs/2.14/generated/torch.nn.BCEWithLogitsLoss.html)支持这一数值实现。

先固定一种损失对照，再调整辅助权重；不同时改变 loss、分辨率、采样和学习率。可围绕 0.1 补充 0.03 / 0.3 的有针对性小试，记录共享参数上动作、检测、MASK 梯度范数；若 MASK 梯度长期主导且动作误差恶化，则减权，而不是继续追求更低分割 loss。只有前期明显冲突时才另试短 warmup。

首轮不升级成大分割网络、不在线运行 SAM、不把 MASK 特征注入动作模型。若显存 / 吞吐是瓶颈，先测 decoder 全分辨率计算和标签加载；必要时再做低分辨率监督的独立对照，并验证小杯子轮廓没有因此消失。

## 6. INJECT 路线：保留原版对照，优先验证可控的 p4 注入

### I0：去主臂后的原注入结构，必须保留的参照

仅改变共同的 8 维输入和正确的数据链路，保留 top / p4 的额外 token 注入。不要将旧九维 INJECT checkpoint 与新八维模型直接当作纯结构对照。

增加诊断：前景 / 背景 gate 分布，注入特征与主视觉特征范数比，动作对合理图像扰动的变化，逐阶段误差，连续动作块一致性和 batch=1 推理耗时。

### I1：首选待验证结构——同网格残差注入

在 top 图像特征送入 Transformer 前，候选形式为：

```text
F_action = F_DET + alpha * Z_FCOS
```

`F_DET` 为原 DET 路径已投影的视觉特征；`Z_FCOS` 为已有 FCOS 中间特征投影，二者均为 512 × 15 × 20。之后沿用图像位置编码，不再额外追加该路 300 个 token。

- 仅改 p4 注入位置及融合形式；第一对照保留原 centerness gate，避免同时换门控造成结果难以解释。
- alpha 初始值 0.05 是小试候选，约束在 0–1 并记录其变化；这是分支比例，不是对输出动作幅度或平滑度的保证。
- 必须有精确关闭注入的测试路径：在相同公共权重、eval 模式下，alpha=0 的动作输出应与 DET 一致至数值容差。正常训练不要让所有注入相关参数都以完全零通路长期失去梯度。
- 不能把“额外 token 乘零”当作同样的关闭测试：token 仍参加注意力、位置编码及归一化，不一定恢复 DET。
- 验证动作损失可训练注入投影，检测监督仍有效，保存 / 重载不改变行为。

选择理由是便于限定额外分支、减少 token 数并建立严格回退对照，而非已经证明它比 token 注入更好。若小试不优于 I0，就保留 I0；不得为了采用新设计而忽略结果。

### I2：有背景注入证据时，再独立试软置信门控

候选用 `sqrt(sigmoid(class_logit) * sigmoid(centerness_logit))` 代替当前 1–2 的 gate，将分类前景信息纳入控制。不做硬阈值开关；训练和推理都使用预测结果，不能训练时用 GT gate、部署时用预测 gate。

这是待实验的评分门控，不是已经校准的前景概率。单独检查低置信、遮挡、边界附近的连续性；只有检测 / 动作梯度冲突有实测证据时，才另试 gate detach 或较小分支学习率，不默认切断全部检测特征的动作梯度。

暂不增加 p2/p3 多层注入，不新增第二套检测网络，不首先改 BatchNorm。训练时可复用 FCOS 已算出的选定层塔特征以减少重复计算，但必须验证输出及梯度等价；这项优化主要针对训练，不能声称它修复正常推理的卡顿。

## 7. 抽搐、缓慢及定位不稳：独立评估与决策树

### 7.1 现在不接机器人也能做的检查

1. 固定相同输入，eval 模式重复推理，排除未关闭 dropout、状态泄漏、错误 episode reset 等造成的不确定变化。
2. 按 episode 顺序读取所有帧，保存每帧预测的完整 100 步动作块；禁止打乱后计算时间指标。原始预测、执行策略加工后的目标分别保存，反归一化后按关节报告。
3. 测量相邻预测对同一未来时刻是否一致：

```text
C(t,h) = abs(pred[t,h] - pred[t+1,h-1]), h >= 1
```

只比较两次预测均有效、且落在 episode 内的时刻；排除 padding。分别报告 h=1–5、6–10、11–30、31–99，以及机械臂 / 夹爪。它量化重新预测时的目标冲突，不等于机器人实际 jerk。

4. 同时报告 h0 MAE、目标一阶 / 二阶差分、方向反转、夹爪开闭事件时差，并与演示轨迹比较。静止预测也很平滑，所以必须同时检查动作幅度、阶段推进与误差，不能只优化差分接近零。
5. 利用同一批原始动作块，离线重放三种无集成执行长度 1 / 5 / 10，以及每步重算的集成 coeff=0.01 / 0.03 / 0.1。系数是诊断候选，不是推荐直接上机的最佳值。每个 episode 重置队列和集成状态，验证在线结果等于按绝对执行时间对齐后的直接加权结果。
6. 开集成时遵循当前策略的每步推理要求，记录最终解析配置，不能以为 `n_action_steps=5` 与集成必然同时生效；不要修改 checkpoint 的 chunk_size 来替代执行长度调节。
7. 用训练帧语义保持的小幅亮度 / 对比度变化检查稳定性，三组共用扰动。不随意水平翻转、移动杯子图像而保留原动作标签；图像错配仅作为依赖性诊断。
8. 做 batch=1 预热后推理性能测试，报告预处理、网络、后处理的 p50 / p95 / p99、实际吞吐和环境。远程 GPU 成绩不能代表真机电脑。首轮仍使用训练对应的 30 Hz 时间语义；30 Hz 总预算约 33.3 ms，不能让网络耗时独占全部预算。

以上仍使用演示 state 和图像，属于 teacher-forced 回放，不是闭环仿真。不能将预测 state 回填后继续配演示图像，便称为真实闭环结果。

### 7.2 根据观测选择措施，不把所有平滑手段一起加上

| 观测 | 优先措施 | 暂不做的事 |
|---|---|---|
| 预测块内平滑，但相邻块对同一时刻分歧大 | 检查输入时序、动作对齐、训练成熟度；比较执行长度与集成；再评估注入设计 | 不先加很强的低通掩盖不一致 |
| 预测块内本身有异常跳变 | 对照演示动作、padding 和分阶段损失；清理确认损坏的样本 | 不把正常夹爪闭合当异常平滑掉 |
| 预测正常，周期 / 图像帧龄抖动大 | 在真实部署电脑测相机读图、解码、串口和日志；定位瓶颈后再优化对应部分 | 不先升级模型、不先改成异步 / 高控制频率 |
| 指令连续，但实测关节仍抖动 | 后续检查校准、执行器跟踪、通信及负载，保留安全限幅和停止机制 | 不凭离线轨迹调整电机控制增益 |
| 框准、动作仍偏 | 看接近阶段各关节误差、空间覆盖和相机一致性，验证视觉到动作映射 | 不只调检测 score / NMS |
| 图像有色带 / 绿块 | 使用带时间戳的实际模型输入确认来源；修采集 / 解码后重评 | 不把孤立预览图直接判为所有测试失败根因 |

如果正确数据和基线训练后仍有预测块内抖动，可单独尝试轻量的“预测动作差分对齐演示动作差分”损失；先仅机械臂，夹爪单独处理。不要以最小化所有动作速度为目标，否则可能制造用户已经遇到的动作缓慢。

## 8. 小试、正式训练与资源安排

### 8.1 按顺序执行，未过验收不进入下一阶段

| 阶段 | 内容 | 验收与后续 |
|---|---|---|
| A：准备 | 8 维契约、标签预览与对齐、MASK 修复回归、INJECT 回退测试 | 数据与梯度正确；无静默跳监督 |
| B：冒烟 | 每候选约 20 步；MASK 另做小样本拟合；保存 / 重载 | loss / 梯度有限，关键分支参与优化，标签有效 |
| C：短训练筛选 | 同一内部 32/8 划分、同一预算，DET / I0 / I1 / M0 各约 10k；检查 2k/5k/10k 趋势 | I1 与 I0 比较；M0 与 DET 比较。接近噪声水平时保留简单方案，不宣布胜出 |
| D：条件追加 | 仅在前景不足、背景 gate 异常等证据出现时，追加 M1 或 I2 的等预算对照 | 不做全参数网格，不把多项修改合并为一次不可解释实验 |
| E：正式三组 | 选定 DET / INJECT / MASK，重新以公共初始化在训练 40 个 episode 上各训练 100k | 20k/40k/60k/80k/100k 统一评估；同时保留固定 100k 比较与候选较优 checkpoint |
| F：训练后报告 | 固定 10 个验证 episode 全量动作、连续性、检测 / 分割及性能报告 | 达标后成为待真机候选；暂不启动真机 |

约 10k 仅是排除明显失败设计、衡量资源的筛选预算，不保证架构收益已经显现。若 I0 / I1 趋势接近，可对二者等量延长小试后再选；不要比较一个 10k 与另一个 20k。正式阶段不直接沿用短试权重，以免混入不同数据划分和训练历史。

正式公共起点沿用原实验：seed=1000、batch=8、chunk_size=100、gripper_loss_weight=3.0、det_weight=1.0、主学习率 1e-5、backbone 学习率 1e-4、AMP 关闭、相同图像归一化、首轮不额外增强。小试应记录完整解析配置，避免 dataclass 默认值暗中改变实验。

保持这些设置是为了可比，不代表它们已最优。若八维模型仍有共同的夹爪误差，下一轮再统一评估夹爪权重或按阶段采样，不把此项只加给某一模型。

### 8.2 并行不是只检查显存

- 既有 `scripts/train_c50_nomaster.sh` 和 readiness 检查针对的是 ACT / DET / INJECT，不是本次 DET / INJECT / MASK，不能原样启动。实施时同步更新组别、标签检查和代码 / 配置摘要。
- 旧的三进程显存测试不代表加入 MASK 后仍可并行。重新测 GPU 峰值、CPU / RAM、数据读取、实际 steps/s 和磁盘。
- 640×480 的 top mask 全训练 40 个 episode 以 float16 常驻，数组本体约 16.4 GiB；50 个约 20.5 GiB，未含解压临时副本等。优先限制 cache，并实测；如需格式变更，再采用按需读取的紧凑存储，不先把所有标签常驻。
- 之前多路 AV1 随机解码已出现严重争用。短试先记录串行和并行吞吐；必要时降低并发或调整数据加载，不能为挤进三进程而只改某组 batch，破坏可比性。
- 既有 checkpoint 每 2k 保存的三组估算总量约 94.8 GiB，超过此前约 55 GiB 空间。建议评估每 5k 保存并保留恢复状态，但必须按新三组实际 checkpoint 大小、标签与临时空间重算；未经授权不删除旧实验。
- 只有 A–D 完成、最新 readiness 通过后，才考虑各自独立 screen 的三组 100k 并行训练。记录环境、完整命令、git diff、数据 / 标签 hash、开始结束时间、退出码及断点恢复信息。

完成后若 80k→100k 的阶段误差、预测一致性仍稳定改善，可提出同预算延长训练的下一轮实验；ACT 作者的建议使其值得检查，但本计划不擅自将 100k 延长为 200k。

## 9. 报告与验收：什么结果才算值得继续

### 必须满足的硬条件

- 没有 master 信号泄漏；数据、动作、相机、标签对齐通过；没有未声明的缺标签。
- MASK 梯度链、损失归一化、推理无标签依赖全部通过；INJECT 关闭回退及保存 / 重载通过。
- 所有比较使用同一 split、同一指标定义；不把训练加权总 loss 与未加权 h0 MAE 混比。
- 分阶段结果保留 unknown。旧阶段记录中约 41.2% 帧未确定；若要细分“抓住 / 抬起 / 搬运”，必须补充事件标注，不直接把旧的 grasp_transport 当成精确单阶段。

### 小试选型参考，不作为成功保证

优先选择同时保住动作准确度、改善一致性或关键阶段误差的方案。可预注册以下工程筛选线：相对同预算参照，机械臂 / 夹爪 h0 MAE 均不恶化超过约 5%，且关键阶段误差或相邻块冲突下降约 10%；同时检查动作幅度与事件延迟，排除“少动所以平滑”。这些数值是拟定筛选容差，不是统计显著性标准，也不是社区公认最佳阈值。

按 episode 报告成对差值和不确定性，给出失败个例；不能把 7,180 个相邻帧当作独立试验。旧视觉报告的三种 sampling seed 不等于三个独立训练 seed。首轮 seed=1000 仅能形成候选排名；资源允许时，对关键结论再用额外训练 seed 复核。

报告应包含：h0 及前 5/10/30/100 步误差、关节和阶段拆分、动作块一致性、目标差分与事件时差、扰动结果、检测中心误差 / IoU、MASK 前景 IoU / Dice、实测延迟分位数、资源和失败样例。分割提高但动作变差，不算本任务优化成功。

未来真机阶段单独制定同起点、同杯子位置、同控制设置的配对试验，记录实际关节与目标、图像时间、周期和任务视频；在安全工作区与可立即停止的条件下进行。可把每候选至少 20 次、目标成功率 90% 作为后续工程目标，并报告样本数与失败类型；它不在本轮执行范围内，少量成功也不证明广泛泛化。
