# C50 真机测试指南（round 2：四模型 -NM，100k）

> 适用模型（HF 公开仓库，用户名 `QYyyyyyyy`）：
> `C50_NOMASTER_ACT_100k` / `C50_NOMASTER_DET_100k` / `C50_NOMASTER_I0_100k` / `C50_NOMASTER_I1_100k`
> 全部 = 100k 步、同一数据集 `formal1_C50_nomaster`（8 维无主臂）、同一超参；**组间唯一差异是检测注入方式**。
> 运行机：真机所在 Ubuntu 侧（`/home/lyj/lerobot`，conda 环境 `lerobotnn`）
> 脚本：`src/lerobot/scripts/control_act_det.py`（与 round 1 相同，md5 `9cdb31cc9c6933225556205a1f219188`）
> round-1 指南（9 维旧模型三臂）仍在仓库根 `C50_真机测试指南.md`；HF 下载通用说明见根目录《模型下载指南.md》。
> 上游离线结论：`docc/报告/C50_阶段E评估报告_2026-09-19.md`。

## 0. 为什么要跑这四个模型

- 离线 val10 × 100k：**ACT-NM 精度第一**（h0_arm 2.6008 / h0_grip 1.6170），**I1 是检测组最优**（2.7461 / 1.6874、事件时序最好）；I1 / I0 / DET 相对 ACT 都未过 §9 预注册筛选线。
- 但离线口径测的是"对演示的复现精度"，**回答不了检测分支的预期收益——对杯位偏移、遮挡、扰动的鲁棒性**。这正是真机要回答的问题。
- 主对比 **ACT-NM vs I1-NM**（无检测 vs 检测组最优）；DET/I0 补全"检测通道三种接法"的一圈。四臂都跑，才能把"检测到底带来什么"说完整。

## 1. 与 round 1 的三个关键差异（先读）

1. **-NM = 8 维 state 接口**：`observation.state` = 5 个关节 + `gripper.pos` + `gripper.load` + `gripper.curr`，**没有 `master_gripper.pos`**；action 6 维。真机脚本按数据集 meta 的 features 组装 state → 必须用 nomaster 数据集 meta（§2.2），**不能**指到 `formal1_C`。
2. 数据集前置只有 **68KB 的 meta/**（不需要视频/parquet 数据体）——训练机上已打好 tar 包（§2.2），scp 过来解开即可。
3. 协议改为**两 block 设计**、四臂 × 10 段（§4）。

## 2. 准备（Ubuntu 侧）

### 2.1 下载四个模型

```bash
cd /home/lyj/lerobot
export HF_ENDPOINT=https://hf-mirror.com
export HF_HUB_ENABLE_HF_TRANSFER=1

dl() { huggingface-cli download "QYyyyyyyy/C50_NOMASTER_$1_100k" \
```

- 每个仓库 = 训练时 checkpoint 的 `pretrained_model/` 内容（7 个文件；ACT ≈207MB，DET/I0/I1 各 ≈236MB）。
- **目标目录必须保持 `checkpoints/100000/pretrained_model` 层级**：真机脚本从路径里取模型名来命名 CSV 动作日志，平铺目录会把四臂都写成 `_outputs.csv`。

- checkpoint 的 `config.json` 里 `pretrained_path` 指向训练机旧路径，**无需手动改**：真机脚本（RecordConfig）会自动用 `--policy.path` 覆盖。

### 2.4 干跑加载（不接机器人）

```bash
cd /home/lyj/lerobot && python - <<'PY'
from pathlib import Path
from lerobot.configs.policies import PreTrainedConfig
from lerobot.datasets.dataset_metadata import LeRobotDatasetMetadata
from lerobot.policies.factory import make_policy, make_pre_post_processors

meta = LeRobotDatasetMetadata("QYyyyyyyy/formal1_C50_nomaster", root="数据集/formal1_C50_nomaster")
names = meta.features["observation.state"]["names"]
assert len(names) == 8 and "master_gripper.pos" not in names, names
print("state(8d):", names)

for m in ["ACT", "DET", "I0", "I1"]:
    ckpt = Path(f"outputs/train/C50_NOMASTER_{m}_100k/checkpoints/100000/pretrained_model")
    cfg = PreTrainedConfig.from_pretrained(ckpt)
    # 必须覆盖：checkpoint config.json 里 pretrained_path 指向训练机旧路径（本地不存在，
    # 不覆盖会被当成 HF repo id 报 HFValidationError）。真机脚本由 RecordConfig 自动做同样的覆盖。
    cfg.pretrained_path = ckpt
    make_policy(cfg, ds_meta=meta)   # 真正从 ckpt 加载权重，状态字典不匹配会在这里报错
    make_pre_post_processors(policy_cfg=cfg, pretrained_path=str(ckpt))
    print("OK", m, cfg.type)
PY
```

## 3. 运行命令（统一模板，复制即用）

把 `<M>` 替换为 `ACT` / `DET` / `I0` / `I1`；block 1 时 `<B>`=`b1`，block 2 时 `<B>`=`b2`。
例：block 1 跑 I1 = 下面命令中 `<M>`→`I1`、`<B>`→`b1`。

```bash
conda activate lerobotnn && cd /home/lyj/lerobot && mkdir -p logs
python src/lerobot/scripts/control_act_det.py \
    --policy.path=outputs/train/C50_NOMASTER_<M>_100k/checkpoints/100000/pretrained_model \
    --policy.n_action_steps=1 --policy.temporal_ensemble_coeff=0.03 \
    --robot.type=so101_follower --robot.port=/dev/ttyACM0 --robot.id=nn \
    --robot.max_relative_target=5 \
    --robot.cameras='{top: {type: opencv, index_or_path: 4, width: 640, height: 480, fps: 30}, gripper: {type: opencv, index_or_path: 2, width: 640, height: 480, fps: 30}}' \
    --dataset.repo_id QYyyyyyyy/formal1_C50_nomaster \
    --dataset.root /home/lyj/lerobot/数据集/formal1_C50_nomaster \
    --dataset.single_task="Cup pick and place" \
    --dataset.num_episodes 5 --dataset.episode_time_s 60 --dataset.reset_time_s 30 \
    --dataset.fps 30 2>&1 | tee logs/round2_<M>_<B>.txt
```

参数说明：

- `--policy.n_action_steps=1 --policy.temporal_ensemble_coeff=0.03`：每步重规划 + temporal ensemble。**四个臂必须用同一个值**——它是本轮的控制变量。默认取 +0.03（`docc/报告/C50_连续动作块诊断报告_2026-09-18.md` §2.6 记录的项目当前配置；round-1 指南里写的是 0.01，两者都是合法配置，差异只影响与 round 1 的严格可比性，不影响本轮四臂对比）。系数本身的 A/B（+0.03 vs −0.03 vs 0 vs 纯 queue_1）是四臂跑完后的单独实验。
- `--robot.max_relative_target=5`：首跑保险，把每步相对位移钳到 5 个单位；跑顺、确认方向正常后可去掉（去掉=动作更快）。
- 相机 640×480@30 必须与训练一致；`index_or_path` 每次会话前用 `lerobot-find-cameras` 确认（历史值 top=4 / gripper=2）。
- `--dataset.single_task`：ACT 系策略不消费该字段（只有 VLA 类策略用到），沿用 round 1 文本即可，四臂一致。
- 按键：`→` 提前结束当前段，`Esc` 结束整个会话。换臂 = 换 `--policy.path` 重开会话（几十秒）。
- 每步动作自动写到 `outputs/control_logs/<时间戳>_C50_NOMASTER_<M>_100k.csv`（target / sent / 夹爪实测）。

## 4. 测试协议（两 block，四臂 × 10 段）

### 4.1 杯位与 block

- 沿用 round 1 在桌面贴的胶带点 P1–P10（若已清理，重贴并**拍照留档**）。覆盖视野中部、含左右两侧，别超出训练采集覆盖的视觉范围。
- **Block 1 = P1–P5，Block 2 = P6–P10。**

### 4.2 会话组织（控制时间漂移）

- 每个 block 开始时**抽签决定四个臂的会话顺序**（写在纸上，事后录进判定表）。
- 按该顺序逐臂开一次会话：`--dataset.num_episodes 5`；会话内杯子按 P 升序摆放（利用 30s reset 间隔换位）。即每臂每 block 5 段。
- 每臂合计 10 段（5+5）；**同一个杯位四个臂都会跑到**（位置配对，便于逐位比较）。
- Block 1 与 Block 2 之间休息 ≥5 分钟；Block 2 重新抽顺序。

### 4.3 每段流程

1. 把从动臂摆回演示起始位姿附近；杯子放到目标杯位；水位补到同一刻度线。
2. 提前 1–2 秒开始录像 → 跑该段（`→` 可提前结束该段）。
3. 按 §5 四阶段判定并记表；**失败也要录像、也要记**。
4. reset 间隔（30s）内摆放下一个杯位。

### 4.4 异常熔断（可选，round 1 已验证管道）

若某臂在 block 1 内连续 3 段"完全不追杯"或 0 成功：停该臂 → 查 `outputs/camera_check/*.jpg` 语义与 control CSV 的 pan 列（杯子左右移动时 pan 是否同向变化）→ 修复后从该 block 起点重跑该臂。

## 5. 判定、失败模式与记录

### 5.1 四阶段判定（同 round 1）

| 阶段   | 标准                           |
| ------ | ------------------------------ |
| 1 抓取 | 夹爪稳定夹住杯身且杯底离台     |
| 2 移动 | 平稳移向目标位置，水无大量洒出 |
| 3 放下 | 松开夹爪后杯子直立不倒         |
| 4 整体 | 1–3 全部通过                  |

### 5.2 失败模式编码

抓空 / 提前闭爪 / 悬停不闭爪 / 撞倒 / 过冲 / 放偏 / 不追杯 / **洒水**（移动途中溢出）/ **掉杯**（途中掉落）/ 停住不动。

### 5.3 记录表与录像

- `判定表_round2.csv` 列：`block, 顺序, 模型, 杯位, 抓取, 移动, 放下, 整体, 洒水, 失败模式, 录像文件, 备注`。
- 录像命名：`round2_{模型}_{杯位}_b{block}.mp4`（如 `round2_I1_P3_b1.mp4`）。

### 5.4 硬性要求

- 四个臂的参数逐字一致，只有 `--policy.path` 的模型名和 tee 文件名不同。
- 同一批杯位；中途不改相机位置、光照、水位线——改了则该 block 作废重跑。
- 全程录像（含失败）；跑完带回：`logs/round2_*.txt`、`outputs/control_logs/*.csv`、判定表、录像、`outputs/camera_check/`。

## 6. 怎么读结果（先定好，防事后解释）

- **主对比 ACT vs I1**。10 段/臂只能给定性结论：按杯位配对比较（同杯位两臂谁成功）；整体成功率差 <3 段说明不了问题（二项波动），但**失败模式**与**方向**（检测臂在偏位/遮挡杯位是否更稳、洒水是否更少）比总数更有信息量。
- 检测臂整体不低于 ACT → 支持"检测通道对扰动更稳"；ACT 仍最好 → 与离线结论一致，如实记录"当前扰动强度下检测通道未见真机收益"。**两种结果都是论文可用材料**。
- 水是最直接的鲁棒性指标：把**洒水 / 掉杯次数单列统计**。
- 论文主表需要每核心模型 ~30 段，本轮每臂 10 段定位为 pilot；若某臂显著胜出再扩试次。

## 7. 常见问题

| 现象                                          | 处理                                                                                                      |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `Control loop is running slower than 30 Hz` | 确认 GPU 空闲（`nvidia-smi`）、相机 fps=30；必要时降分辨率                                              |
| 策略不动 / 不追杯                             | 先看`outputs/camera_check/*.jpg` 语义（"蒙眼"跑与坍缩无法区分）；再看 control CSV 的 pan 是否随杯位变化 |
| 首条动作幅度大                                | 每段开始把从动臂摆到演示起始位姿附近                                                                      |
| 抓取前悬停 / 不闭爪                           | 看 CSV 的`target.gripper.pos` vs `gripper_actual` 与 `sent.*`                                       |
| 相机画面异常                                  | 已连读 10 帧仍异常 → 手动跑`lerobot-find-cameras` 复核 index；发绿/发暗先等 2 秒（暖机瞬态）           |
| 报 HFValidationError（把路径当 repo id）      | 检查`--policy.path` 是否指向真实存在的本地目录                                                          |
| 报 8 维/9 维 state 不匹配                     | `--dataset.root` 指错了数据集：必须 `数据集/formal1_C50_nomaster`，不是 `formal1_C`                 |
