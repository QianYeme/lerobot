# Formal3 四模型真机测试指南

适用模型：Formal3 NOMASTER fit48、seed 1000、100k checkpoint。目标是安全、可复现地比较 Diffusion、DET、C1显式框条件和Phase辅助模型。离线指标不是闭环成功率；首次真机必须从单episode、10秒低速冒烟开始。

## 1. 下载部署文件

模型仓库：

- `QYyyyyyyy/F3_P4_DIFFUSION_BASE_s1000`
- `QYyyyyyyy/F3_P4_DET_BASE_s1000`
- `QYyyyyyyy/F3_P4_DET_C1_STATE_s1000`
- `QYyyyyyyy/F3_P4_DET_PHASE_W010_s1000`

训练数据仓库：`QYyyyyyyy/formal3_kind_merged_nomaster_fit48`。真机控制只读取其中的`meta/`以获得8维state、6维action和名称；图像归一化及state/action统计由checkpoint内保存的pre/postprocessor加载，不要用旧`formal1_C`元数据替代。

```bash
cd /home/lyj/lerobot
mkdir -p outputs/deploy/formal3 数据集/formal3_deploy_meta logs

python - <<'PY'
from huggingface_hub import snapshot_download

models = [
    "F3_P4_DIFFUSION_BASE_s1000",
    "F3_P4_DET_BASE_s1000",

    "F3_P4_DET_PHASE_W010_s1000",

for name in models:
    snapshot_download(
        repo_id=f"QYyyyyyyy/{name}",
        local_dir=f"outputs/deploy/formal3/{name}",
    )

snapshot_download(
    repo_id="QYyyyyyyy/formal3_kind_merged_nomaster_fit48",
    repo_type="dataset",

```

下载后每个模型目录必须包含`config.json`、`model.safetensors`、`policy_preprocessor.json`、`policy_postprocessor.json`及对应safetensors。`数据集/formal3_deploy_meta/meta/`必须包含`info.json`、`stats.json`和`tasks.parquet`。

## 2. 上机前Gate

1. 使用GitHub `det`分支最新代码；旧代码无法识别Phase配置字段。
2. `lerobot-find-port`确认从动臂串口；不要默认永久是`/dev/ttyACM0`。
3. `lerobot-find-cameras`确认top和gripper编号；USB重连后编号可能变化。
4. 从动臂摆到演示起始姿态附近，leader主臂移出工作区。
5. 急停/断电手段在手边；首轮杯中仅保留能维持训练视觉语义的少量水，清除机器人周围电子设备。
6. 首轮保持`--robot.max_relative_target=5`，只运行10秒。若动作被持续钳位，先比较CSV的`target.*`与`sent.*`，不得直接取消限幅。
7. 检查脚本启动时保存的`outputs/camera_check/top.jpg`和`gripper.jpg`，确认相机语义、方向、曝光和遮挡均正确后才按回车。

## 3. checkpoint干加载

该步骤不连接机器人，只验证四个配置与pre/postprocessor可读取：

```bash
python - <<'PY'
from pathlib import Path
from lerobot.configs.policies import PreTrainedConfig
from lerobot.datasets.dataset_metadata import LeRobotDatasetMetadata
from lerobot.policies.factory import make_pre_post_processors

root = Path("outputs/deploy/formal3")
meta = LeRobotDatasetMetadata(
    "QYyyyyyyy/formal3_kind_merged_nomaster_fit48",
    root="数据集/formal3_deploy_meta",
)
assert meta.features["observation.state"]["shape"] == (8,)
assert meta.features["action"]["shape"] == (6,)
for path in sorted(root.iterdir()):
    cfg = PreTrainedConfig.from_pretrained(path)
    cfg.pretrained_path = path
    make_pre_post_processors(policy_cfg=cfg, pretrained_path=str(path))
    print("OK", path.name, cfg.type, cfg.input_features["observation.state"].shape)
PY
```

四行都必须打印`OK`且state维度为8。

## 4. 10秒冒烟命令

先设置现场参数：

```bash
MODEL=F3_P4_DET_BASE_s1000
ROBOT_PORT=/dev/ttyACM0
TOP_CAMERA=4
GRIPPER_CAMERA=2
```

运行：

```bash
python src/lerobot/scripts/control_act_det.py \
  --policy.path="outputs/deploy/formal3/$MODEL" \
  --policy.n_action_steps=1 \
  --robot.type=so101_follower --robot.port="$ROBOT_PORT" --robot.id=nn \
  --robot.max_relative_target=5 \
  --robot.cameras="{top: {type: opencv, index_or_path: $TOP_CAMERA, width: 640, height: 480, fps: 30}, gripper: {type: opencv, index_or_path: $GRIPPER_CAMERA, width: 640, height: 480, fps: 30}}" \
  --dataset.repo_id=QYyyyyyyy/formal3_kind_merged_nomaster_fit48 \
  --dataset.root=/home/lyj/lerobot/数据集/formal3_deploy_meta \
  --dataset.single_task="Cup pick and place" \
  --dataset.num_episodes=1 --dataset.episode_time_s=10 --dataset.reset_time_s=30 \
  --dataset.fps=30 2>&1 | tee "logs/${MODEL}_smoke.log"
```

四个模型只修改`MODEL`。Phase模型推理不需要阶段标签；C1使用检测器预测框，不读取GT框。Diffusion训练配置本身是`n_action_steps=1`，这里显式覆盖保持统一。

建议冒烟顺序：`DET_BASE → DET_PHASE_W010 → DET_C1_STATE → DIFFUSION_BASE`。C1已确认检测准确但坐标对动作影响偏弱，因此它是诊断候选，不应预设为最佳模型。

## 5. 冒烟判停条件

出现任意一项立即`Esc`或断电：

- 机械臂向桌面、相机、底座或人体快速运动；
- 连续大幅左右抽搐；
- 夹爪挤压杯体且水明显晃动或可能洒出；
- 控制循环明显失速并持续累积动作；
- 相机画面与训练语义不一致；
- `target`持续大幅变化但`sent`被限幅、机器人在原地反复挣扎。

`Ctrl+C`不是正常episode结束方式；优先使用脚本的`Esc`，让`policy.reset()`、preprocessor和postprocessor按正常控制流程管理会话。无论如何，每次新模型都重新启动进程，并把机械臂精确复位到标记姿态，不依赖手动“大概相同”。

## 6. 正式小规模对照

只有四个模型都通过10秒冒烟后才进入：

- 杯位：left、center、right三个固定胶带点，位置不得超出训练覆盖；
- 每模型每杯位先做1次，共12段；模型顺序在不同杯位轮换，避免时间顺序偏差；
- 每段60秒上限，段间精确复位；
- 记录顶部相机、外部视频和`outputs/control_logs/*.csv`；
- 逐段记录：起步方向、接近误差、闭爪、稳定保持、抬升、放置、释放、洒水、碰撞和人工中止。

暂不启用`temporal_ensemble_coeff`。此前`0.01`表现缓慢、`0.1`伴随大幅抽搐；应先获得无ensemble基线，再把平滑参数作为独立变量测试。也不要在同一轮同时取消`max_relative_target`并修改ensemble，否则无法判断变化来源。

## 7. 测后带回

- `logs/*_smoke.log`及正式日志；
- `outputs/control_logs/*.csv`；
- `outputs/camera_check/*.jpg`；
- 每段外部录像；
- 杯位照片与复位姿态照片；
- 逐段判定表和所有人工中止原因。

这些证据用于区分：模型目标错误、限幅导致不动、控制频率不足、夹爪机械/负载问题，以及C1显式坐标仍被策略忽略。
