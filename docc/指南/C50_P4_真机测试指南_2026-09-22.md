# C50 P4 真机测试指南

本指南用于测试 P4 的两个候选模型：`DIFFUSION_NM` 和备用的 `C1_DROP`。离线结果不能替代真机证据；第一次只做单 episode、低速、可急停测试。

## 1. 测试前门槛

确认：

- 机械臂已脱离障碍物，杯子装水不超过安全高度；操作者始终能触发急停。
- 从动臂处于训练集相同的正对工作区中间初始姿态。
- `/dev/ttyACM0`、top 相机和 gripper 相机已经通过独立预览确认。
- 记录 `robot.max_relative_target`、fps、相机索引和 checkpoint，不要在一轮比较中临时修改。
- 第一轮只运行 1 个 episode、20--30 秒；出现碰撞、持续抽搐、明显偏航、夹爪失控或洒水，立即按 Esc 或急停。

`control_act_det.py` 在每个 episode 开始会调用 `policy.reset()`、`preprocessor.reset()` 和 `postprocessor.reset()`；Ctrl-C 只保证进入 `finally` 完成断开，不应把它当成下一次运行的复位动作。每次重新启动前手动把机械臂和杯子恢复到预设位置。

## 2. 环境与日志

```bash
cd /root/autodl-tmp/lerobot/lerobot-main
mkdir -p logs outputs/control_logs
export PYTHONPATH="$PWD/src:$PYTHONPATH"
```

脚本启动后会保存 `outputs/camera_check/top.jpg` 和 `gripper.jpg`，先确认视角正确，再按回车继续。每个控制周期会写入 `outputs/control_logs/<timestamp>_<model>.csv`，包含 target、sent 和实际夹爪位置。

## 3. 首选：Diffusion

```bash
python src/lerobot/scripts/control_act_det.py \
  --policy.path=outputs/train/C50_P4_DIFFUSION_NM_s1000/checkpoints/100000/pretrained_model \
  --robot.type=so101_follower --robot.port=/dev/ttyACM0 --robot.id=nn \
  --robot.max_relative_target=5 \
  --robot.cameras='{top: {type: opencv, index_or_path: 4, width: 640, height: 480, fps: 30}, gripper: {type: opencv, index_or_path: 2, width: 640, height: 480, fps: 30}}' \
  --dataset.repo_id formal1_C \
  --dataset.root /home/lyj/lerobot/数据集/formal1_C \
  --dataset.single_task="Cup pick and place" \
  --dataset.num_episodes 1 --dataset.episode_time_s 30 --dataset.reset_time_s 30 \
  --dataset.fps 30 2>&1 | tee logs/P4_DIFFUSION_NM_real.log
```

Diffusion checkpoint 配置为 `n_action_steps=1`。当前离线网络中位耗时约 49.8 ms；若日志持续提示控制循环低于 30 Hz，停止测试，不要通过提高动作步数掩盖延迟。

## 5. 每次测试记录

填写以下结果，不把“开始向中间移动”记为成功：

| 项目 | 记录 |
|---|---|
| 模型/checkpoint |  |
| 初始杯位 | left / left-front / front / right-front / right |
| 首个有效动作方向 | 正确 / 中间偏置 / 反向 / 不动 |
| 接近 | 成功 / 失败；是否抽搐 |
| 抓取 | 成功 / 偏夹 / 未闭合 |
| 闭爪后稳定 0.2--0.5 s | 是 / 否 |
| 抬升 | 成功 / 松爪 / 抖动 |
| 放下 | 成功 / 过冲 / 未释放 |
| 洒水/碰撞/急停 |  |
| CSV 日志路径 |  |

第一轮只比较首动作、接近和抓取是否稳定。只有单次测试无碰撞、无洒水且夹爪保持后，才增加 episode 数；不要在同一轮同时改变 `max_relative_target`、fps、相机索引或 checkpoint。

## 6. 结果判定

真机结果必须结合 CSV 和人工观察。teacher-forced 离线 MAE、阶段误差和网络耗时只能用于候选筛选，不能替代抓取成功率、放下成功率、洒水率和动作抽搐记录。
