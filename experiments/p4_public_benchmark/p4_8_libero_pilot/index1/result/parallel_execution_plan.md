# 用户要求的并行测试方案（G2通过后执行）

当前没有训练/模型benchmark排队，不能自动越过原型来源门槛。

1. 合同内每模型100步smoke：前20步warmup，后80步计时；分别测单路与双路，模型/优化器/RNG/数据顺序独立。记录包含decode/I/O的实用吞吐、GPU/内存，进程启动耗时单列，不能将启动差异误当稳态收益。只有合计实用吞吐提高且内存安全才双模型并行；探针更新不混入正式预算。
2. 正式ACT/P1各seed1、10k，2k/5k/10k保存完整optimizer/RNG；从同样受控step0重新开始，探针不追加到正式步数。后台唯一控制器与每模型PID/数据split/配置hash均登记，SSH断开继续。
3. 闭环模型评估按实测并发容量2–4个worker分配同一份20条任务：两模型×各10个配对init ID。建议预注册init10..19、eval seed1（待G2审核），与已做G1 smoke init0..2分开；这只是pilot，不宣称官方默认init0..9的复现。不要查看这些评估场景来挑原型。
4. 每个(model,init_id)唯一，hard reset、原定步数上限/控制频率/相机/动作接口一致；记录成功/失败、视频、seed和耗时。模型交替下发，在条件内平衡顺序；按task失败不能自动补新episode。工程重试保留失败且单列。
5. P1 ON/OFF只用一份冻结P1 checkpoint做敏感性诊断；不等同训练模块消融。没有新模型/训练seed、没有额外预算、没有全套任务自动扩展，也不影响P4.7真实机器人。
