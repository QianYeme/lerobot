## 1. Single Research Question

This round answers only:

> In the already collected master-arm teleoperation data, after controlling as much as possible for gripper position, gripper motion, and commanded gripper target, does `gripper.load` still show a consistent difference between FREE_CLOSE and CUP_CONTACT?

This is a retrospective analysis.

It does not claim the evidence is equivalent to a controlled intervention.

---

## 2. Why This Round Exists

A strict F1R controlled collection was proposed to compare:

```text
same fixed arm pose
same frozen gripper closing program
FREE_CLOSE vs CUP_CONTACT
```

However, the user already has a targeted teleoperation set containing:

```text
5 × FREE_CLOSE
5 × CUP_CONTACT
```

with raw actuator signals and video.

These teleoperated trials were not generated by an identical frozen closing program, so they cannot directly substitute for controlled intervention evidence.

Before asking the user to collect more robot data, this round tests whether the existing data already contain sufficiently strong residual contact-related information.

---

## 3. Evidence Boundary

Allowed scientific interpretation:

> Existing teleoperation data support / do not support a repeatable contact-associated residual in `gripper.load` after retrospective motion matching.

Forbidden interpretation:

- controlled causal proof of contact sensing;
- calibrated force sensing;
- true force estimation;
- proof that a force-aware policy will improve grasping;
- proof that `load` is independent of all operator / phase / trajectory confounds.

All conclusions remain:

```text
EXPLORATORY_ONLY
```

Rules:

- do not use `current` to define contact;
- uncertain frames remain excluded / uncertain;

FREE_CLOSE trials are treated as no-object-contact only if the video / collection setup confirms there was no object between the fingers.

## 7. Analysis Populations

Construct two primary sample populations.

### A. FREE_CLOSE pool

Frames from the gripper-closing portion of the 5 FREE_CLOSE trials.

### B. CUP_CONTACT pool

Frames from the 5 CUP_CONTACT trials, separated into:

```text
PRECONTACT
CONTACT
```

The primary comparison is:

```text
FREE_CLOSE
vs
CUP_CONTACT / CONTACT
```

A secondary diagnostic comparison may use:

```text
CUP_CONTACT / PRECONTACT
vs
CUP_CONTACT / CONTACT
```

but this secondary comparison must not replace the cross-condition FREE_CLOSE comparison.

## 8. Confound Variables

Retrospective matching must use only non-force variables.

Primary matching variables:

```text
gripper.pos
delta gripper.pos
previous commanded gripper target
delta commanded gripper target
```

Optional, only if reliably available in all trials:

```text
short-window gripper velocity
short-window command velocity
```

Forbidden matching variables:

```text
gripper.load
gripper.current
condition label-derived hidden features
absolute trial progress
episode/trial ID
future frames
```

---

## 9. Standardization

Fit all matching-variable standardization parameters using the FREE_CLOSE pool plus CUP_CONTACT PRECONTACT frames only.

Do not include CUP_CONTACT CONTACT frames when fitting normalization statistics used for distance calculation.

Reason:

> Contact frames are the target condition whose residual signal is being tested.

Record scaler statistics in:

```text
result/matching_scaler.json
```

---

## 10. Primary Matching Procedure

For every valid CUP_CONTACT CONTACT frame:

1. search FREE_CLOSE frames only;
2. find the nearest frame in standardized confound-variable space;
3. use Euclidean distance;
4. perform one-to-one greedy matching without replacement within each analysis pass;
5. do not use load/current during matching.

Primary maximum standardized matching distance:

```text
0.75
```

This threshold is frozen before analysis.

Do not relax it after seeing the number or direction of matched load differences.

---

## 11. Secondary Matching Procedure

If the primary threshold yields insufficient coverage, do not silently replace it.

A pre-authorized sensitivity analysis may also report:

```text
distance <= 1.00
```

This is secondary only.

The final scientific category must clearly separate:

```text
primary 0.75 result
secondary 1.00 sensitivity
```

The 1.00 analysis cannot be used to claim that the primary criterion passed.

No further threshold search is allowed.

---

## 12. Matching Coverage

Report:

```text
number of eligible CONTACT frames
number of matched CONTACT frames
number of matched FREE_CLOSE frames
coverage ratio
per-trial number of matches
distance distribution
```

Primary minimum for interpretable retrospective evidence:

```text
at least 3/5 CUP_CONTACT trials
with >= 10 primary-threshold matched pairs each
```

and:

```text
at least 40 primary-threshold matched pairs total
```

If this is not met, the scientific outcome must include:

```text
UNRESOLVED_MATCHING_COVERAGE
```

The analysis may still report descriptive plots, but cannot promote the result to residual-signal evidence.

---

## 13. Balance Audit

After matching, compute standardized mean differences for each matching variable.

Primary target:

```text
|SMD| <= 0.20
```

for all primary matching variables in the pooled primary-threshold matched set.

Also report per-variable:

```text
before matching SMD
after matching SMD
```

If any primary variable remains:

```text
|SMD| > 0.20
```

the result must be flagged:

```text
RESIDUAL_CONFOUND
```

and cannot be promoted to strong residual-load evidence.

---

## 14. Primary Load Analysis

For each matched pair:

```text
delta_load =
load(CUP_CONTACT_CONTACT)
-
load(FREE_CLOSE)
```

Report:

1. paired load difference distribution;
2. pooled mean;
3. pooled median;
4. standard deviation / IQR;
5. positive-difference fraction;
6. per-CUP_CONTACT-trial mean / median;
7. per-trial positive-difference fraction;
8. matched-pair scatter;
9. load-vs-position visualization.

Do not report Newtons.

---

## 15. Trial-Level Replication Requirement

The main interpretation must be trial-level, not only pooled-frame-level.

A residual signal is considered more credible only if it repeats across CUP_CONTACT trials.

Report for each of the 5 contact trials:

```text
n_matches
mean_delta_load
median_delta_load
positive_fraction
matching_distance_mean
matching_distance_p95
```

A large pooled effect driven by one trial must be explicitly identified.

---

## 16. Contact-Onset Diagnostic

For CUP_CONTACT trials with reliable video-derived onset:

- align load traces around contact onset;
- show a short pre-contact and post-contact window;
- subtract a local pre-contact baseline if useful;
- report per-trial direction of post-contact change.

This is diagnostic support only.

It cannot replace retrospective FREE_CLOSE matching.

## 17. Current Analysis

`gripper.current` is secondary.

Repeat the same paired residual analysis for current:

```text

-
```

## 18. Statistical Summary

Because matched frames within a trial are correlated, do not treat every frame as an independent experiment.

Primary uncertainty summary:

```text
trial-level / cluster-aware
```

Use one of:

- paired trial bootstrap, or
- cluster bootstrap by CUP_CONTACT trial.

Recommended bootstrap:

```text
2000 resamples
seed = 20261016
```

Report exploratory 95% percentile intervals.

Do not use p-values as the main decision rule.

## 19. Primary Outcome Categories

### `TELEOP_RESIDUAL_LOAD_PROMISING`

Use only if all are true:

1. primary matching coverage passes;
2. post-match balance passes (`|SMD| <= 0.20`);
3. at least 4/5 CUP_CONTACT trials, or all available qualifying trials if only 3–4 qualify, show the same positive load-difference direction;
4. pooled matched load difference is positive;
5. effect is not dominated by a single trial;
6. contact-onset diagnostics are directionally compatible with the matched analysis.

Interpretation:

> Existing teleoperation data contain a repeatable load residual associated with cup contact after partial retrospective motion control.

This remains exploratory and does not equal controlled causal evidence.

---

### `WEAK_TELEOP_RESIDUAL_SIGNAL`

Use if:

- coverage and balance pass,
- pooled residual is positive,
- but trial-level consistency is weak, overlap is large, or one trial dominates.

Interpretation:

> Existing data suggest a possible residual contact signal but are not strong enough to justify confident contact-aware policy design without controlled confirmation.

---

### `NO_CLEAR_TELEOP_RESIDUAL_GAIN`

Use if:

- coverage and balance pass,
- but matched load residual is near zero / inconsistent / mixed across trials.

Interpretation:

> The current teleoperation data do not provide clear residual evidence beyond matched motion conditions.

This does not prove `load` is useless.

---

### `UNRESOLVED_MATCHING_COVERAGE`

Use if primary matching coverage fails.

---

### `UNRESOLVED_RESIDUAL_CONFOUND`

Use if matching coverage passes but post-match balance fails.

## 23. Plain-Language Meaning

This round does not ask the user to collect anything new.

It takes the already collected:

```text
5 empty-gripper trials
+
5 cup-contact trials
```

and tries to compare moments where:

```text
gripper position is similar
gripper motion is similar
command is similar
```

Then it asks:

```text
when the cup is actually being contacted,
is load still systematically different?
```

If yes, the existing data already provide useful evidence for continuing toward a lightweight contact/load regulator.

If no, or if the trials cannot be matched cleanly, the project should not hide that limitation. At that point a small controlled confirmation experiment may still be needed before force-aware policy training.
